# ROBYLO Elementor Atomic and custom code audit

November 19, 2026 · ChatGPT/Codex · Read-only website audit for owner review

## Findings

The current homepage, shared header and footer, mobile menu, and portfolio carousel already use Elementor. The main duplication is a legacy navigation stack in the installed child theme and two site-wide Elementor JavaScript snippets. Their files and snippets loaded on eight sampled routes, while the elements they target were absent from every sampled DOM. They are candidates for controlled retirement after checking older entry points.

**The live theme and the GitHub theme are different.** WordPress reports the active child theme as `ROBYLO Starter 1.0.5`, directory `wp-content/themes/robylo/`, with Hello Elementor 3.5.2 as the parent. The repo’s `theme/robylo-child/` is a minimal 0.1.0 starter. The draft About active-link patch in PR #21 targets the repo starter and is absent from the audited site. Using the starter as a drop-in replacement would be a separate theme migration. Do not delete the active child theme or its required parent as part of this audit.

**No code changes or removals were made.** Keep means preserve the observed behavior or narrowly scoped exception. Replace means native functionality is already present or is a concrete replacement candidate, subject to the stated checks. Review means equivalence or ownership needs more evidence before any change.

## What Elementor already owns

- Installed Elementor and Pro 4.4.1. Kit **5744** exposes **21 variables and 54 global classes**. The kit supplies Manrope, the monochrome palette, gutter and spacing tokens, and responsive tag defaults. Role classes such as `rb-display-xl`, `rb-section-title`, and `rb-item-title` intentionally differ from the tag defaults. That is the existing hierarchy, not a duplicate CSS system.
- The component inventory exposes 14 entries. The nine ROBYLO-named definitions are Button 5864, Base Section 5869, Heading and Text 5877, Header 5886, Footer 5889, Section Head 6010, Service Row 6013, Project Tile 6016, and Approach Step 6019. The other five older components were inspected as inventory. Some have native hover, shadow or transform settings. They need a usage check before any cleanup.
- Header template **5892** uses the Header component, Atomic links, and native menu button `344e021f`. Popup **5996** uses Theme Builder conditions and native popup controls. Footer **5893** uses the shared Footer component. Existing About links in both menus already point to `/about/`.
- Home **5894** uses native Atomic carousel `063712a`, native arrows and Elementor Pro’s carousel handler. The **six** existing projects and their links are Elementor content. The staged Quickzy end correction uses a local responsive margin calculation on `79928cc9`. The staged Approach numbers use absolutely positioned Atomic text and decorative attributes. Neither change adds a separate script or a carousel library.
- Active Coming Soon **5858**, internal page skeletons, the staged About page **6197**, the diagram, Studio Plates, and service lists are stored as Elementor documents. Main site composition uses Atomic grid, flex, tag semantics, local styles, responsive settings and component properties. Generated `uploads/elementor/css/{base,default,global,local}-*` files are render output. A declaration appearing in these files does not by itself identify handwritten CSS.
- WordPress owns routes and menus. AIOSEO owns the observed SEO output. The SiteGround optimizer, AI assistant, Turnstile integration, Elementor frontend libraries and Cloudflare beacon are platform/plugin output. No ROBYLO rewrite of those libraries was identified.

## Suggested order after approval

1. Back up the active child theme and record source provenance, Theme Builder conditions, assigned WordPress menus and the two Elementor snippet settings. Keep the current site configuration as the baseline for a rollback.
2. On an isolated preview, disable the two legacy Elementor snippets individually. Inspect old templates, shortcode pages, stored conditions and legacy project listings first. Test native Header/Popup, portfolio links, homepage/internal preview and the anonymous Coming Soon page after each step.
3. With legacy consumers mapped, test disabling the old theme assets or migrate to a separately validated minimal child theme. Compare responsive layout at 1440, 1024, 768, 390 and 320px, desktop/mobile navigation and tab order, touch and Escape focus return, admin toolbar, reduced motion, forms, carousel edges and theme/editor styling. If changing themes, verify menus, templates, Customizer options and plugin conditions before removing the inactive copy.
4. Resolve About’s current state separately from theme cleanup. Verify visible and semantic state in the existing desktop Header and mobile Popup before merging the PR #21 code. Keep everything in a review branch until the underlying theme source and runtime are verified.
